## 1. 事实与变更边界

当前华昇元数据强制 CREATE 四行、QUERY 四行、CALLBACK 两行非终态映射，以及空错误映射表；该约束继续有效。状态与错误表不是任意资金动作配置引擎，不能通过填表实现退款、切供或无界重试。

用户已确认本次仅修回调和映射页面，恢复能力另做。本轮包括官方失败回调的交付数量语义、映射管理可操作性与版本说明，以及后端提前拒绝违反封闭模板的追加操作。原单核实、错误策略、有限补单和人工结案不属于本轮，不以完成本轮修复宣称上述恢复扩展已经完成。

正式证据：[回调](https://s.apifox.cn/57114177-5188-44e4-99f8-2a8581e4be12/487479396e0)、[下单](https://s.apifox.cn/57114177-5188-44e4-99f8-2a8581e4be12/486554275e0)、[流程](https://s.apifox.cn/57114177-5188-44e4-99f8-2a8581e4be12/9165623m0)、[错误码](https://s.apifox.cn/57114177-5188-44e4-99f8-2a8581e4be12/9168637m0)。文档核验不等同于供应商实机验收。

## 2. 回调数量与资金事实

### 2.1 订购数量与交付数量

PLACE/CONFIRM/QUERY 的 num 表示原单订购数量，本期严格为 1。CALLBACK 的 num 表示成功交付数量，不能沿用订购数量校验：

- SUCCESS 必须提供整数 num=1，list 恰一完整 type201，并与冻结原单订购数量核对。
- FAILED 允许整数 num=0 或省略 num，list 允许省略或空数组；显式 null、字符串、负数、非零值与非空 list 均拒绝。允许省略来自正式字段的“可选”定义；零交付由 FAILED 的正式语义确定，不伪造 num=1。
- 协议事实保留 num 的省略与显式 0 区别，Inbox 完整事实摘要也必须区分，避免同 nonce 改写报文被当作同内容。
- 应用层失败步骤的有效交付数量为 0；订单订购数量从锁后原单/checkpoint 取得，仍严格为 1。身份、金额、退款语义、既有/待核资产及终态冲突检查全部保留。

### 2.2 检查点与兼容

新 FAILED 回调观察保存实际有效交付数量 0，禁止改写成 1。检查点 V1 为 CALLBACK/FAILED 增加 num=0 的合法组合；订单端点与成功回调仍要求 1。历史 V1 已保存的 CALLBACK/FAILED/num=1 只作为既有观察读取兼容，不代表新回调入口接受该组合。旧编码键与 AAD 不变化，不改历史密文和 Inbox 摘要。

失败回调只有在身份、金额与原单一致，无已交付/待核资产，无冲突且未反向终结时，才经既有受控资金入口恰一次释放买家预占。已成功原单收到失败回调仍登记冲突，不能释放。解析失败、同 nonce 异内容、资产冲突及事务失败不确认消息。

## 3. 映射管理契约

### 3.1 后端元数据与查询

AdapterMetadata 增加默认允许追加的映射管理声明；华昇覆盖为封闭模板，并提供中文业务说明。继续由服务端元数据定义，不在前端散落华昇适配器标识来猜测权限。

映射查询在原两列表外追加版本与管理投影：connectorVersionId、versionNo、versionStatus、currentPublishedVersionId、initializeAllowed、statusAppendAllowed、errorAppendAllowed、mappingDescription。版本字段语义沿连接器版本 DDL；三个 allowed 字段是当前版本/映射/适配器规则计算出的可操作性，不替代 HTTP 权限与写入口守卫。

初始化仅允许 DRAFT 且两张映射表均为空。追加仅允许 DRAFT 且适配器允许。华昇禁止逐条追加状态和错误映射；直接请求后端也须在 insert 前拒绝，避免留下无法发布的草稿。初始化继续一次生成完整十行模板。QNM 与其它可扩展适配器沿既有封闭枚举和 retryable 一致性约束追加。

映射写事务首先以既有 `selectByIdForUpdate` 当前读锁定版本，再判断草稿身份；成功写入后更新该版本行的乐观锁版本和更新时间。与验证结果落库/发布共享版本行围栏：已开始但基于旧映射观察的验证须因 expectedVersion 不符拒绝；已验证版本不能被滞后的初始化/追加请求插入映射。全部映射和版本更新在同一供应链事务，更新失败全部回滚，不把页面 allowed 快照视为持续写权限。

### 3.2 前端展示与竞态

页面显示当前查看版本、生命周期和当前已发布版本。查看草稿时明确提示草稿不等于派单版本；显示华昇十行模板和空错误表的业务含义。按后端 allowed 字段限制初始化/追加，未知或缺失规则默认不可写。

切换连接器或供应商后，异步返回只能应用到仍匹配的所选版本；旧响应不得覆盖新选择的规则或映射。实际执行按钮时再次核对当前加载的版本及规则，不能只禁用模板按钮。通用错误分类改用后端已接受的四个封闭分类选项，并将 RETRY_SAFE 与可重试值联动，避免原有 TIMEOUT/BUSINESS 示例误导用户。

追加请求发出后即使切换到新表单，旧请求的成功/失败提示与 finally 也不能关闭新会话或改变其 loading；按捕获的弹窗会话编号隔离完成事件。初始化请求同样在完成时核对加载请求序号及供应商、连接器、版本身份，旧操作不得提示或刷新新选择。currentPublishedVersionId 未发布时必须明确序列化为 null，不能被 NON_NULL 配置省略后触发前端缺规则保护。

## 4. 恢复能力扩展延期

用户于 2026-10-12 明确选择“本次仅修回调和映射页面，恢复能力另做”。维持既有未知结果查单、次数/期限、人工保留及无自动补 PLACE 的规则。未来如扩展原单核实、有限补单或凭外部证据强制释放，须另行设计权限、证据、代次、次数、资金事实与审计要求；本文件不作为这些新行为的实施授权。

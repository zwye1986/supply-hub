# SKU 销售建议价以供应价为基准自动重算设计

> 日期：2026-10-19。状态：用户批准的本地实现及自动化门禁已完成；尚未执行共享环境迁移或部署。实施清单见 `../plans/2026-10-19-suggested-sale-price-supply-base.md`。
> 已确认：页面新增选择“供应价”，不再新增选择“销售建议价”；随供应价自动重算；无有效供应价允许保存公式并进入待计算，供给恢复后自动计算。
> 本文扩展商品中心设计 §5.3.1。2026-10-18 的实现与发布记录保留其历史语义。

## 1. 范围与实施前基线

- 当前建议价规则 `SuggestedSalePriceRule.Base` 仅支持 MARKET_PRICE 与历史 SUGGESTED_SALE_PRICE；`SuggestedSalePriceCalculator` 仅在商品保存时计算。
- 通用分销价/销售价计算器已经支持 SUPPLY_PRICE，但属于另一套公式，不等于 SKU 建议价已支持供应价。
- `SupplierOfferEligibilityService.resolveMinimumSupplyPrices` 是现有最低有效供货价解析入口。本文复用当前正式发布版本口径，禁止采用商品中心部分旧注释中已经废止的身份列回退。
- `PricingDependencyChangedEvent` 当前同步重算平台、分销商和项目定价，未重算 SKU 建议价。主动发布/上下架、部分供应商/连接器变更已有事件；不能据此宣称时间跨界及全部失效入口已经覆盖。
- `sc_platform_sku.suggested_sale_price` 及三层定价版本的建议价快照当前为非空；`PriceDependencies.suggestedSalePriceCents` 是基本类型 long。待计算不能直接复用 0 作为缺省。
- 现有定价根锁工具明确禁止持根锁后反向取得商品行锁，生命周期重算不能直接调用复合商品保存。
- 前端以 `/Users/mac/codespace/supplychainhubweb` 为准，现有基数字典过滤器只放行 MARKET_PRICE。

## 2. 业务规则

### 2.1 新选项与公式

1. CUSTOM 新选项来自 system 字典 `supply_chain_suggested_sale_price_base`，允许 MARKET_PRICE（市场价）及 SUPPLY_PRICE（供应价）。SUGGESTED_SALE_PRICE 仅保留历史兼容，未知编码不开放。
2. 供应价取同一 SKU 在当前数据库时间、现有一期数量 1 口径下的最低有效供货价。供应商、平台商品、Offer、当前履约版本、连接器、能力、库存来源和有效期均按共享解析器判断；不使用草稿、不使用不含税展示值，不选择特定供应商。
3. 公式及精度复用建议价计算器：先乘百分比，再执行加/减/乘/除，最终 HALF_UP 到 CNY 分；由服务端计算。前端提交规则，不提交可信基数或计算结果。
4. 供应价为 0 与供应价缺失不同：存在真实 0 分候选时按 0 参与建议价公式；交易定价仍沿用现有 0 供货价不可售规则。负结果、溢出、除零不能被截断或强制改为 0。
5. 供应价来源改变但最低金额未变时，不无故发布新的下游价格版本；刷新到期检查依据即可。建议价规则改变即使金额未变，也须保存新规则与依赖身份。

### 2.2 待计算、失败和恢复

- 新 SKU 无供给仍可保存 SUPPLY_PRICE 公式；响应中的当前建议价为 null，状态 DEPENDENCY_MISSING，页面显示“待计算：暂无有效供应价”。
- 最后一个有效供给失效时，同样将当前建议价置为不可用。最后一次成功金额可单独显示为历史参考，不能出现在当前有效金额字段或作为新报价输入。
- 有效供给恢复后自动计算，不要求运营重新保存；恢复时须显式清空旧原因，不能被 MyBatis 默认忽略 NULL 的更新策略遗留。
- 公式参数非法时拒绝用户保存。已合法保存的公式因后续供应价变化产生负结果/溢出时，进入 CALCULATION_FAILED；公式保留，下游依赖该建议价的定价不可用。此业务计算失败不阻断供应商品下架或供应商停用等正确的供给操作。
- 数据库失败、版本归属损坏等系统异常继续上抛并回滚事务，不伪装成普通待计算；不得在事务部分成功后继续开放新报价。正式Offer或三层定价的非空当前指针必须引用存在且归属匹配的版本；子层重建不得把损坏指针解释为首次配置并覆盖人工规则。历史Offer空指针仍沿用既有无有效供给语义，不扩大拒绝范围。
- FIXED、EQUAL_MARKET_PRICE 和历史 SUGGESTED_SALE_PRICE 规则不因供应价变化改写自身金额；原有下游供应价依赖重算照常进行。
- 在途订单、历史价格版本与首次永久冻结报价金额保持原值，重放不重新签价；新报价与新订单按既有当前准入规则判断。

## 3. 方案比较与推荐

1. **推荐：同步处理主动变更，持久化 Timer 处理时间跨界，读侧实时校验。** 主动操作提交前完成建议价与下游重算；无操作的到期由 Timer 推进，读侧防止调度延迟产生旧价。覆盖页面、交易和重启恢复。
2. **仅访问时计算。** 实现较小，但无人访问时不更新状态，无法满足完整的自动联动，且容易遗漏某个读入口。
3. **仅异步或周期扫描。** 写入口较轻，但供给变化到处理完成存在旧价窗口，仍需交易校验和可靠补偿。本轮不采用它作为唯一机制。

## 4. 数据模型与唯一取值入口

### 4.1 独立建议价计算状态

推荐新增供应链表 `sc_sku_suggested_price_state`，一个 platform_sku_id 对应一行；表间不建立物理外键。职责是保存动态计算结果和依赖状态，不保存第二套人工公式。

- `platform_sku_id`：唯一身份，指向 SKU。
- `rule_digest`：已计算规则的规范化摘要；比较时排除服务端生成的基数快照。
- `calculation_status`：READY、DEPENDENCY_MISSING、CALCULATION_FAILED，使用枚举与 CHECK。
- `effective_price_cents`：当前有效建议价，非 READY 必须 NULL；READY 必须非负且非 NULL。
- `base_price_snapshot_cents`：本轮供应价基数，缺失为 NULL。
- `last_valid_price_cents`、`last_valid_calculated_at`：最近一次成功结果，仅供历史参考。
- `unavailable_reason`：稳定原因编码，READY 必须 NULL。
- `next_check_at`：候选当前版本下一有效期边界；空表示没有已知时间跨界，不代表永远有效。
- `calculated_at`、`revision`：计算事实时间与状态修订号；无变化检查不重复递增。

SKU 原规则 JSON 仍是人工公式唯一来源。SUPPLY_PRICE 的服务端基数快照从状态投影回响应，客户端快照一律忽略。

为保持现有锁方向，SUPPLY_PRICE 的动态结果不从生命周期事件反向写回 `sc_platform_sku`。该 SKU 原 `suggested_sale_price` 对新规则只保留旧模式兼容存储值，绝不能作为当前供应价建议价使用；新建行该列沿用现有技术默认值，但所有对外响应及定价依赖必须由统一解析入口返回 null/有效结果，不能泄漏技术默认 0。

新增 `SuggestedSalePriceResolver` 统一选择权威来源：SUPPLY_PRICE 根据当前规则和有效供给计算/校验结果，其他模式沿用现有金额。禁止业务侧直接从 SKU 原列读取 SUPPLY_PRICE 的有效金额。按代码引用盘点覆盖复合详情、管理列表、标品、供应商品、分销商品、项目商品及定价依赖；纯数据库历史诊断须同时读取规则与计算状态。

从 SUPPLY_PRICE 切换到 FIXED/等于市场价时，在商品写事务中恢复原模式金额来源并失效动态状态；旧客户端把“修改前建议价”作为基数时，必须使用解析后的当前有效金额，无有效金额则按既有规则校验拒绝，不能取兼容列或历史参考。

### 4.2 下游依赖与版本快照

- 将通用 `PriceDependencies.suggestedSalePriceCents` 改为可空 Long；三层新价格版本允许建议价快照为 NULL，以真实表达待计算。
- 仅以建议价为基数的分销价/销售价公式因该依赖缺失返回空价及稳定不可用原因；市场价和供应价公式按其自身依赖计算。既有无供给、零供给和利润隐藏判定保持。
- 对新增迁移后的旧行不洗历史金额、不重写已冻结版本。DDL 放宽快照空值并增加计算状态表/约束；通过新增量同步修订 SKU 金额列与规则 JSON 的 COMMENT，明确 SUPPLY_PRICE 当前结果由计算状态表提供，不再沿用“所有规则结果都物化于原金额列”的表述。DTO、OpenAPI、序列化和所有自动拆箱调用同步修改，禁止 null 默认成 0。
- system 追加新字典变更集加入 SUPPLY_PRICE（供应价，排序 2）；已执行的 018 及其历史校验不修改。供应链进程不查询 system 字典表。

## 5. 重算顺序、事务与并发

### 5.1 统一编排

一次处理顺序固定为：读取当前规则及有效供给 → 计算动态建议价状态 → 更新平台定价 → 更新分销商定价 → 更新项目定价。不能靠多个 Spring 监听器的注册顺序保证先后，也不能计算后再递归发送同一个依赖事件。

将现有 `PricingDependencyChangedEvent` 收口到单一编排入口，显式调用建议价状态处理与原三层重算。整个主动变更在同一供应链 RC 事务中完成；无平台价格身份或首版定价时，也必须能保存建议价待计算状态，再按原默认初始化约束处理，不能被旧重算入口的提前 return 跳过。

### 5.2 锁与写入责任

- 继续复用现有平台定价身份根锁，跨 SKU 先收齐目标、按 ID 升序锁定；没有根身份时按初始化协议建立唯一根，不能依赖不存在行的查询锁作为互斥证明。
- 商品保存继续先锁商品再进入定价根锁。生命周期写入口已持供应商/连接器/Offer 锁时，仅追加定价根锁及独立计算状态锁，不反向取得商品排他锁。
- 动态状态写入限定在独立表，不更新包含 @Version 的整个 SKU，防止覆盖运营刚保存的名称、库存、状态或新规则。
- 持根锁后清除当前供应链 SqlSession 一级缓存并重读 SKU 规则、供给及父配置；保存新规则和它对应的计算状态在同一外层事务内提交。
- 人工平台/分销商/项目定价的预览与保存统一取动态有效建议价；进入计算前校验时间和规则摘要，不能复用锁前对象。
- 报价刷新入口也须遵守平台→分销商→项目的锁序。重构现有 `ensureCurrentProjectVersion` 先取得项目定价锁后再补偿的路径，禁止持有子层锁时回调根层刷新，禁止通过 REQUIRES_NEW 规避未提交数据或破坏报价幂等事务。
- 并发商品改规则与供给变更、批量交叉 SKU、到期回调与重新发布均须真实 MySQL 两事务验证。不能仅凭设计声明无死锁。

## 6. 触发覆盖与时间有效性

### 6.1 主动变化

核对并补齐：Offer 正式发布/发布变更/上下架/移除，供应商启停/拉黑，连接器发布/退役及当前版本切换，库存来源激活，平台 SPU/SKU 启停及规则保存。当前系统没有独立库存来源停用、连接器停用/重启入口；已发布能力不可编辑，能力变化通过新版本发布生效，本轮不新增这些业务接口。新增合作关系、商业草稿和验证草稿不触发正式供货价联动。

重新启用平台商品须重新解析有效供给并恢复建议价；建议价待计算不能反过来作为平台商品或 FIXED 供给上架的前置条件，否则新商品永远无法建立首个供给。现阶段正式发布仍保持已有 FIXED 范围，不放开 DISCOUNT/REALTIME，不引入“供应价依赖建议价”的循环。

### 6.2 报价生效、到期与重启

- 复用 `PersistentTimer` 注册候选当前版本的 validFrom/validTo 边界任务，任务按版本 ID 与边界类型形成幂等键，使用数据库时间与既有时区转换。
- 首次保存 SUPPLY_PRICE 规则时也为已有候选版本登记边界；不能只在今后的供应商品发布时调度。下一边界必须考虑全部候选，不只是当前最低价，以覆盖非最低候选未来生效/失效。
- Timer 与触发源状态在同一事务落库，沿用现有调度身份账本；Handler 仅委派 catalog 的事务编排入口，不直接写领域表。
- 旧版本任务、重复任务及延迟重试均重新读取当下规则、指针与供给集合，只更新当前事实，不重放旧金额；规则已切换则无害结束。
- 采用现有 Timer 重启恢复、重试及死信机制；部署验收须验证实际 Timer 开启、处理器注册、停机后到期及启动后恢复。不开启 Timer 的实例不能宣称具备无人访问时自动重算。
- 列表/详情 GET 保持只读，通过统一解析器以同一数据库时间计算当前展示金额与状态，不能把过期物化结果当成现价；分页批量加载供给，避免 N+1。无访问时由持久化任务推进落库。
- 首次报价在原事务内、锁序允许的位置先校验并刷新当前建议价及受影响的三层版本，再冻结；供给在事务快照后变化遵循既有冻结边界。已存在永久冻结报价按原合同重放，不因新建议价改写。

## 7. 前端与接口

- 下拉允许字典 MARKET_PRICE、SUPPLY_PRICE，仍过滤历史和未知值；字典整体缺失时提示配置问题，不能写死回退。
- 新增 SKU 默认保留原市场价选项；用户可切换供应价并填写公式。无供给时允许提交，显示待计算说明。
- 详情和列表统一返回当前有效 `suggestedSalePrice`（可空）、`suggestedSalePriceStatus`、`suggestedSalePriceUnavailableReason`；历史参考使用独立字段 `lastValidSuggestedSalePrice` 与其时间。`lastValidSuggestedSalePriceCalculatedAt` 沿用平台LocalDateTime的毫秒时间戳序列化契约，OpenAPI明确integer/int64；前端复用已有formatDate，兼容文本日期、数值和数字字符串，不能直接拼接时间戳。动态状态表缺行且依赖有效时允许只读即时计算，不显示兼容列。
- 编辑详情补充当前 `supplyPrice` 及服务端建议价基数快照。展示当前供应价、公式与计算状态；前端不承担权威计算。
- SUPPLY_PRICE 保存仅提交公式，不回传服务端快照/状态/参考金额。无关编辑与并发供给变更不得把旧页面金额写回，不能依靠前端缓存决定最终建议价。存量SUPPLY_PRICE规则收到旧客户端“仅金额”请求时拒绝歧义输入；切换固定价必须显式提交FIXED规则，两字段均省略则保留公式。
- 页面刷新或重新打开后读取最新状态；本轮不增加 WebSocket/推送。这里的“自动”指服务端随供给变化计算，不承诺已打开页面无需刷新实时跳数。
- 原历史 SUGGESTED_SALE_PRICE 只读回显、保存省略、主动重新设置语义继续保持；此次新选项不影响通用批量定价已有的基数集合。

## 8. 计算、错误与日志边界

- 纯计算器不依赖 Spring、Mapper 或 system 字典；解析器取价，编排器写状态及发布下游版本，领域职责分开。
- 用户提交非法规则使用稳定业务错误码；依赖缺失与计算失败返回独立状态/原因。数据库故障保留因果，由既有 HTTP/Timer 终结边界收敛。
- 新增日志遵守 `2026-10-04-logging-standardization-spec.md`：业务状态变化提交确认后记录；无变化检查 DEBUG，批量汇总，任务重试与恢复沿用现有追踪作用域，不新建线程池或修改公共 encoder。
- Timer 后台执行使用本次独立 traceId/executionId，并在 finally 恢复工作线程原 MDC。任务号关联同一边界的重试。候选版本未保存发布 traceId，因此不把后来重查者的 traceId 写成历史来源；幂等负载仅包含 SKU、不可变版本及边界，不包含每次请求变化的追踪字段，防止同键负载碰撞。已有可靠来源时才关联 originTraceId，不伪造历史来源，不打印密钥、原始凭据或交易敏感报文。

## 9. 自动化与验收门禁

1. 纯计算：两种新选基数、历史兼容、四运算、分精度、0/缺失区分、负数/溢出、合法规则后续失败与恢复。
2. 前端真实 SFC：字典标签与过滤、新建无供给可保存、待计算/失败/历史参考分离、供应价规则提交不带旧金额、旧规则保留、模式往返。
3. 字典：新增迁移首次/次轮幂等，018 不变，额外管理员数据保留；供应链新表约束与 nullable 版本快照在完整 MySQL Liquibase 上验证。
4. 生命周期：最低价改变、非最低价改变、草稿无影响、发布后生效、上下架/供应商/连接器/能力/库存失效与恢复，首次供给发布可打通待计算商品。
5. 时间：当前最低价过期后切换次低价、无供给待计算、未来低价生效、已有报价在规则保存前创建、Timer 重启/重复/迟到/死信、GET 不写库、报价不使用过期建议价。
6. 下游：依赖建议价与不依赖建议价的公式分别验算，READY 原因清空、无变化不发布多余版本；保存/生命周期/报价使用同一有效结果。
7. 并发：商品规则变更与供给改价、平台根锁等待后重读、批量交叉 SKU、报价与 Timer 并发、乐观锁及全事务回滚，禁止通过删锁或放宽资格使测试通过。

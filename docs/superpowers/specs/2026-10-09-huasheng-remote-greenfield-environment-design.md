## 3. 新库选项

### 3.1 推荐：pro143 独立 MySQL 8.4 容器

新 Compose 项目及新数据卷持有专用数据库 `supply_chain_huasheng_e2e`；应用账号仅允许该库。数据库不发布公网端口，与独立供应链实例通过该项目私有 Docker 网络通信。应用不得使用 root 凭证；root仅用于容器数据库/账号初始化，秘密在远端0600配置文件持有，不写仓库。

优点：当前主机已有镜像，无需借用无创建权限的旧RDS应用账号，不触碰已有RDS库。限制：这是独立远端测试数据库，不是生产RDS/TLS验收；不得将私有容器网络传输证明描述为生产网络安全通过。

### 3.2 备选：RDS 专用新库及新账号

由有权限的管理员创建新库和仅该库的专用账号，提供受控连接配置；应用仍使用独立容器。使用VERIFY_IDENTITY及实际可信CA，禁止因TLS失败降级关闭校验。不能使用旧应用账号尝试越权创建、从未知配置中寻找高权限凭证或清空旧库。

优点：更接近现有部署形态。限制：目前未发现有权限的新库创建入口，需要管理员配套，不能宣称资源已就绪。

## 4. 最小独立应用与入口

候选目录为pro143 `/data/aifuli-test/supplyhub-greenfield`，Compose项目名 `supplyhub-greenfield`；容器名、数据卷、网络、配置和日志目录全部专用。供应链候选宿主入口59190，专用入口代理候选59180；只放行受控入口或SSH隧道，不开放数据库/缓存，不更改共享59080/58190。

复用现有system的真实登录、RBAC和字典服务，以及必要时member的已注册RPC；仅经HTTP/RPC访问，供应链不读system/member表。该复用意味着管理身份不是“全系统空白”，新库验收范围明确为供应链业务数据。沿现有显式Feign注册和实际认证客户端配置，不用mock权限或任意伪造login-user绕过网关。

新供应链实例不得注册到现有供应链服务名下形成混合负载均衡。优先关闭该实例Nacos Discovery和共享Config导入，使用明确的隔离配置及现有system/member固定RPC地址；所有后台worker只处理新库。新Redis实例和新的独立认证/信封/指纹/限频密钥，不拷贝旧业务密钥或旅通开关。ELK先保持关闭，沿现有日志规范记录本环境本地日志。

入口可先通过SSH隧道访问远端专用代理，运行实际管理前端指向该入口；这是远端实例验收，不假称公网入口已经发布。如需远端静态站和华昇回调公网地址，在pro197新增独立站点，域名/DNS及路径需先确认，不覆盖当前supplyhubtest站点。首次真实交易前依据实际华昇协议核对是否必须可达回调，不能用旧系统回调接收本实例订单。

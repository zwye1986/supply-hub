# 供应商供货范围按类型与分类匹配设计

## 1. 已确认规则与范围

用户于2026-10-20确认：供应商供货匹配不校验可售品类；商品类型编码相同，商品分类相同或配置分类为商品分类的祖先即可。继续支持父分类覆盖子分类、归档不断链和最具体配置优先。

本设计取代2026-09-07表单字典设计d3的可售品类匹配条件、旧SKU选品的三码全等规则，以及2026-09-11商品中心设计d46/§4.19中新增供应商品“不按供货配置三码收窄”的约定。只修改供应链后端，不改前端、数据表、唯一索引、字典或共享框架。

## 2. 唯一匹配算法

输入为供应商的供货配置快照、SPU商品类型/分类以及catalog所有的类目归属解析器。

1. 商品类型或分类为空/空白：无匹配。可售品类无论相同、不同或为空，都不参与供货匹配。
2. 对每条配置，商品类型必须字符串相等；分类通过`ProductCategoryCoverageService.CoverageResolver.covers`判断，相同即覆盖；不同时要求均为已知类目码且配置为SPU分类祖先。枚举名只全等，不与类目码混配。
3. 多条命中按配置类目层级取最深者。较浅层级冲突不影响唯一更深配置；最深层级仍有多条命中则为歧义，不能取第一条，也不能回退较浅层配置。
4. 唯一命中返回配置行，`supply_scope_id`与缺省供货上限均继承该行。无匹配写入口返回`SUPPLIER_OFFER_OUT_OF_SCOPE`，歧义写入口返回`SUPPLIER_SCOPE_CONFLICT`；查询入口不展示无匹配或歧义SPU，不因无关SPU歧义导致整页报错。
5. 算法封装为`tradecore.supply.application.SupplierSupplyScopeMatcher`无状态静态匹配器，不查询数据库、不抛业务异常；新增/编辑和两个选品服务复用。类目树仍只由catalog的`ProductCategoryCoverageService`加载，一次业务调用复用一个解析器；不在supply或旧SKU查询中直接依赖类目Mapper。

## 3. 写入口与保留边界

`SupplierCooperativeProductService.matchScope`委托唯一算法并映射现有错误码。新增、兼容batch-draft和编辑共用。父SPU/SKU启用、外部SKU必填、报价、数量、未退役关系唯一、默认下架及READ_COMMITTED事务保持不变；批量第二行拒绝仍回滚第一行写入。不得修改正式报价/定价版本。

`sellableCategory`字段仍存储、返回，供货配置及商品写入仍校验其合法性；显式列表筛选仍可用。只有供货范围匹配不比较它。供货配置仍按原三元组唯一，不自动合并跨品类同类型同分类行，不回填已有Offer的配置引用。

已核查`SupplierOfferPublicationService`和`SupplierOfferEligibilityService`的发布/有效供给守卫不比较供货配置可售品类，本轮不新增发布或下单阶段的供货范围回查。

## 4. 选品查询

### 4.1 旧SKU池

`PlatformSkuQueryService.page`传入supplierCode时，不再构造三码字符串键，而对候选启用SPU执行唯一匹配算法；再按符合范围的SPU ID分页SKU。继续排除供应商已有未退役Offer，保留买方/项目交集约束、关键字与显式查询过滤。显式sellableCategory查询条件属于用户主动检索，不是配置准入，保持兼容。

### 4.2 聚合选品

仅`excludeAddedSupplierOffers=true`场景新增范围收窄：先校验供应商身份，再读取该供应商范围，查询对应商品类型的启用SPU并执行唯一算法，将允许SPU ID与现有候选集合取交集，在SPU分页前过滤。类型和分类必须按同一配置成对命中，禁止分别取并集后产生交叉组合。无范围/无命中直接返回total=0空页。

保留现有类目ID、类型Tab、关键字、父子启用及排除已有合作商品过滤，范围条件与它们取交集；聚合明细不再做范围后置过滤，确保total与分页一致。普通商品列表、buyerCode选品以及未打开该开关的supplierCode已供商品筛选不受影响。前端已有categoryId条件不会被取消，本次不扩展前端展示范围。

### 4.3 已配置合作商品列表重匹配（2026-10-20追加，用户批准最小读侧修复）

仅修改`SupplierCooperativeProductService.page`及其私有筛选/投影方法。供货配置删除重建后，列表不能以旧`supply_scope_id`是否仍存在决定商品可见性；带任一显式筛选条件时，对该供应商已有未退役Offer关联SKU/SPU批量加载，使用全部当前配置及同一次类目快照执行`SupplierSupplyScopeMatcher`，唯一命中后再按命中配置的品类/类型/分类应用请求筛选。以允许的platform_sku_id约束最终数据库分页，不做分页后剔除。多个筛选参数精确匹配命中配置，与原配置字段检索语义一致；品类仅是显式检索，不参与匹配算法。

回显优先使用当前唯一命中配置；未带筛选时保留全部未退役Offer（包括范围外、配置为空、歧义及缺主数据），无法唯一匹配则沿用旧配置读取/空值回显，不任取歧义配置。最具体匹配必须先于显式筛选，不能通过先筛配置回退到较浅层。已有商品的SPU/SKU停用不额外隐藏，列表不是新增准入。

不改replaceAll、supply_scope_id、状态、报价/数量、正式版本、发布资格、定价、路由、listLive、两个新增选品接口或前端，不迁移或修复数据库。当前匹配只影响列表筛选与配置字段投影，不把新范围供货上限重新继承到已有Offer。每次page只加载一次当前配置与类目解析器，批量候选限制于该供应商的已有未退役Offer。

测试须覆盖真实Spring配置替换（原行删除新ID）、三SKU分页total/翻页、父分类覆盖与最具体优先、类型/分类不匹配或无配置时带筛选隐藏但不筛选仍可查、显式品类、歧义及不回退浅配置、停用商品仍可管理；断言查询不改变Offer全行/版本及新增选品排除结果。

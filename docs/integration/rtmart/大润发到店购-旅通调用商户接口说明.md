# 大润发到店购 — 旅通调用商户接口说明

> 适用对象：旅通（大润发 POS / H5）   
> 协议来源：`docs/integration/rtmart/大润发到店购渠道分销接口.docx`「二、商户接口」  
> 更新日期：2026-09-02

本文只覆盖**旅通调用商户**的 6 个入站接口。Word 文档「一、旅通接口」（获取扫码购授权地址 / 订单详情页地址）由旅通提供、中台出站调用，不在本文范围。

## 1. 约定

| 项 | 值 |
|---|---|
| 测试环境 Base URL | `http://apitest.kalaiwang.com` |
| 路径前缀 | `/api/rtmart` |
| 方法 | `POST` |
| Content-Type | `application/json` |
| 字段命名 | snake_case |
| 认证 | 旅通私钥 SHA1withRSA 签名，中台用旅通公钥验签 |
| 时间戳 | Unix 秒；容差默认 **180 秒**（3 分钟） |
| 金额单位 | **分**（整数） |

`app_key` 由联调分配。中台按配置把 `app_key` 映射为内部 `projectId` + `channelCode`，请求体**不要**传项目 ID。

## 2. 接口一览

| 编号 | 名称 | 路径 | 实现类 |
|---|---|---|---|
| ① | 获取会员信息 | `POST /api/rtmart/member/resolve` |
| ② | 创建订单 | `POST /api/rtmart/order/create` | 
| ③ | 查询支付单状态 | `POST /api/rtmart/payment/query` |
| ④ | 取消支付流水 | `POST /api/rtmart/payment/cancel` | 
| ⑤ | 申请退款 | `POST /api/rtmart/refund/apply` | 
| ⑥ | 查询退款状态 | `POST /api/rtmart/refund/query` | 

## 3. 通用协议

### 3.1 公共请求头字段

六个接口都带以下字段（接口①再加 `token`，接口②～⑥再加各自业务字段）：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `app_key` | string | 是 | 旅通授权 key，须与中台配置一致 |
| `version` | string | 是 | 协议版本，联调示例为 `v1` |
| `timestamp` | long | 是 | Unix 秒。超出容差返回 `E4002` |
| `nonce_str` | string | 是 | 随机串 |
| `sign` | string | 是 | SHA1withRSA 签名，标准 Base64 |

接口②～⑥会对 `(app_key, nonce_str)` 做 Redis 防重放：同一 nonce 在容差窗口的 2 倍时间内重复提交，返回 `E4001`「请求已处理，请勿重复提交」。接口①当前不做 Redis 防重放。

### 3.2 签名算法（SHA1withRSA）

与 Word 文档一致：

1. 取请求 JSON 中**除 `sign` 外**、值为非 `null` 的字段。
2. 按 **key 字典序**排序。
3. 无分隔拼接 `key + value`（value 用字符串原样，数值转成十进制字符串）。
4. 对 UTF-8 字节做 `SHA1withRSA`，签名为**标准 Base64**。
5. 中台用旅通提供的公钥验签。

`null` 字段不参与签名；空字符串会参与。布尔值按 Word 约定转 `"1"` / `"0"`，当前六个接口均无布尔字段。

验签失败返回 `E4004`；`sign` 缺失同样 `E4004`。`app_key` 与配置不一致返回 `E4003`。

**密钥交换**：公钥/私钥由双方线下配置，本文不收录密钥明文。

### 3.3 通用响应

成功：

```json
{
  "result": "success",
  "code": "E0000",
  "msg": "",
  "data": { }
}
```

成功时 `data` 对象必须输出该接口文档列出的**全部字段**。数值类空值发 JSON `null`；字符串类「可为空」字段发空字符串 `""`。禁止因 null 省略键（旅通按字段名解析）。接口⑥的 `refund_fee` 在失败/人工处理时按第 9 节例外可以不出现。

失败：`data` 固定为空数组 `[]`（不是 `null`）。

```json
{
  "result": "fail",
  "code": "E4003",
  "msg": "app_key 不正确",
  "data": []
}
```

| 字段 | 说明 |
|---|---|
| `result` | `success` / `fail` |
| `code` | 见第 10 节 |
| `msg` | 状态描述 |
| `data` | 成功为对象；失败为 `[]` |

## 4. 接口① 获取会员信息

旅通 H5 / POS 拿入口 `token` 向商户换会员资料。token 由中台在换 HOME/DETAIL 地址时签发，旅通原样回传。

| 项 | 值 |
|---|---|
| 地址 | `POST /api/rtmart/member/resolve` |
| 测试完整 URL | `http://apitest.kalaiwang.com/api/rtmart/member/resolve` |

### 4.1 请求

```json
{
  "app_key": "xxxx",
  "version": "v1",
  "timestamp": 1734019200,
  "nonce_str": "O4mxapNiWL1KvF6j",
  "sign": "Base64签名",
  "token": "..."
}
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `app_key` | string | 是 | 授权 key |
| `version` | string | 是 | 协议版本 |
| `timestamp` | long | 是 | Unix 秒 |
| `nonce_str` | string | 是 | 随机串 |
| `sign` | string | 是 | 对 `app_key/version/timestamp/nonce_str/token` 签名 |
| `token` | string | 是 | 入口凭证。签发值为 `tk-...`|

签名字段（有值才进规范串）：`app_key`、`version`、`timestamp`、`nonce_str`、`token`。

### 4.2 成功响应

```json
{
  "result": "success",
  "code": "E0000",
  "msg": "",
  "data": {
    "user_code": "247",
    "mobile": "13800000000",
    "user_name": "张三",
    "company_code": "L0000A"
  }
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `user_code` | string | 商户会员编号。实现上等于签发入口时冻结的 `buyerUserId`（商城会员 id 的十进制字符串），不是从 token 明文解析 |
| `mobile` | string | 会员手机号，中台实时向 member-server 查询，必有值 |
| `user_name` | string | 会员姓名，允许空 |
| `company_code` | string | 企业组。取入口凭证签发时冻结的快照，不是请求参数 |

Word 文档示例里 `company_code` 写成固定 `L0000A`，那是当时联调商品组。实现按凭证快照返回，可能随项目配置变化。

### 4.3 失败与业务语义

| 场景 | code | msg |
|---|---|---|
| 凭证无效 / 过期 / 已用 / 已撤销 / 会员不存在 | `E4001` | 授权凭证或会员资料无效 |
| member-server 暂时不可用 | `E5000` | 会员资料暂时不可用 |
| 其它运行时异常 | `E5000` | 系统错误 |

处理顺序：验签 → 剥离 `CXB_` → 按 token SHA-256 认领一次性凭证（ACTIVE→PROCESSING）→ 按冻结档案版本查会员 → 成功则凭证 USED，失败则释放或撤销。

token **不含**手机号。`mobile` / `user_name` 来自 member-server；`user_code` / `company_code` 来自凭证冻结快照。

## 5. 接口② 创建订单

POS 下单后请商户创建支付单并返回收银台地址。

| 项 | 值 |
|---|---|
| 地址 | `POST /api/rtmart/order/create` |

### 5.1 请求

```json
{
  "app_key": "xxx",
  "version": "v1",
  "timestamp": 1744191949,
  "nonce_str": "5KfeeG8vVAXpp734",
  "sign": "Base64签名",
  "order_id": "LT-ORDER-001",
  "trade_id": "LT-TRADE-001",
  "user_code": "247",
  "company_code": "L0000A",
  "total_amount": 1650,
  "order_time": 1744191948,
  "order_type": 1,
  "shop_code": "1001",
  "shop_name": "宜山路店",
  "dynamic_code": null
}
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| 公共五字段 | | 是 | 见 3.1 |
| `order_id` | string | 是 | 旅通订单号。与渠道编码构成永久幂等键 |
| `trade_id` | string | 是 | 旅通支付流水号。一笔订单可有多笔流水；与渠道编码构成支付幂等键 |
| `user_code` | string | 是 | 会员编号，须与接口①返回的 `user_code` 一致 |
| `company_code` | string | 是 | 企业组编号 |
| `total_amount` | long | 是 | 应付金额，单位分 |
| `order_time` | long | 是 | 支付单创建时间，Unix 秒 |
| `order_type` | int | 是 | 支付单类型。**当前仅支持 `1`（线下扫码购）**，其它值 `E4001`「order_type 当前仅支持 1」 |
| `shop_code` | string | 是 | 门店编号 |
| `shop_name` | string | 是 | 门店名称 |
| `dynamic_code` | string | 否 | 动态码。Word 约定 `order_type=2` 时必填；本期不开放类型 2，该字段可空 |

签名字段：公共五字段 + `order_id` `trade_id` `user_code` `company_code` `total_amount` `order_time` `order_type` `shop_code` `shop_name` `dynamic_code`（`dynamic_code` 为 null 时不参与）。

`user_code` 必须能解析到启用的渠道用户绑定，否则业务失败（映射为 `E4001`）。

### 5.2 成功响应

```json
{
  "result": "success",
  "code": "E0000",
  "msg": "",
  "data": {
    "out_trade_no": "SC-PAY-...",
    "cashier_url": "https://mall.example.com/h5/tbsg-cashier.html?orderNo=...&token=...&source=rtmart"
  }
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `out_trade_no` | string | 商户支付单号（中台 `outTradeNo`） |
| `cashier_url` | string | POS 打开的采购商 H5 收银台地址。收银台签发失败时可能为空，旅通须按原 `out_trade_no` 走接口③查询，不要自行重创 |

幂等：同一 `(channelCode, order_id)` / `(channelCode, trade_id)` 重复创建会走中台幂等，不重复建单。

{
  "app_key": "xxx",

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|

| `order_id` | string | 否（协议有，业务定位不依赖） | 旅通订单号。参与签名；中台按 `trade_id` 查支付流水 |
| `trade_id` | string | 是 | 旅通支付流水号 |
| `user_code` | string | 是 | 会员编号 |

```json
{
  "result": "success",
  "code": "E0000",
  "msg": "",
  "data": {
    "out_trade_no": "SC-PAY-...",
    "pay_status": 1,
    "pay_fee": 1650,
    "pay_time": 1744192000,
    "transaction_id": "CASHIER-TXN-..."
  }
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `out_trade_no` | string | 商户支付单号 |
| `pay_status` | int | `0` 待支付，`1` 支付成功，`2` 取消支付 |
| `pay_fee` | Integer | 支付金额，单位分。待支付、取消、支付成功均必填，取中台流水建单金额 |
| `pay_time` | Integer | 支付时间，Unix 秒。未支付、取消填 `0`；支付成功为实际支付时间 |
| `transaction_id` | string | 支付流水号（可为空，支付成功时必传）。待支付/取消为空字符串 `""`，键必须保留；`pay_status=1` 时必须非空，取收银台流水号，缺失则 `E5000` |

待支付示例：

```json
{
  "result": "success",
  "code": "E0000",
  "msg": "",
  "data": {
    "out_trade_no": "SC-PAY-...",
    "pay_status": 0,
    "pay_fee": 1650,
    "pay_time": 0,
    "transaction_id": ""
  }
}
```

内部状态到协议 `pay_status`：

| 中台流水状态 | 内部码 | 返回 `pay_status` |
|---|---|---|
| 已支付 | 20 | `1` |
| 已取消 | 40 | `2` |
| 待支付 / 处理中 / 失败 / 人工 | 其它 | `0` |

## 7. 接口④ 取消支付流水

POS 取消该笔支付流水。Word 约定：**未支付则关单；已支付则转退款**。中台按此实现，成功响应仍只回 `out_trade_no`。

| 项 | 值 |
|---|---|
| 地址 | `POST /api/rtmart/payment/cancel` |

### 7.1 请求

字段与接口③相同：公共五字段 + `order_id`（签名可选空）+ 必填 `trade_id` `user_code` `company_code`。

```json
{
  "app_key": "xxx",
  "version": "v1",
  "timestamp": 1736735099,
  "nonce_str": "pNSWK05LQXiS1PRW",
  "sign": "Base64签名",
  "order_id": "LT-ORDER-001",
  "trade_id": "LT-TRADE-001",
  "user_code": "247",
  "company_code": "L0000A"
}
```

### 7.2 成功响应

```json
{
  "result": "success",
  "code": "E0000",
  "msg": "",
  "data": {
    "out_trade_no": "SC-PAY-..."
  }
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `out_trade_no` | string | 商户支付单号 |

内部若已支付会转退款 Case，协议层不额外返回退款单号；退款进度走接口⑤⑥。

## 8. 接口⑤ 申请退款

POS 推送退款。支持同一支付流水多次退款（排队 + 金额校验）。

| 项 | 值 |
|---|---|
| 地址 | `POST /api/rtmart/refund/apply` |

### 8.1 请求

```json
{
  "app_key": "xxx",
  "version": "v1",
  "timestamp": 1736735103,
  "nonce_str": "C4hxMv73KARsIRpK",
  "sign": "Base64签名",
  "order_id": "LT-ORDER-001",
  "trade_id": "LT-TRADE-001",
  "refund_bn": "LT-REFUND-001",
  "refund_fee": 5634,
  "user_code": "247",
  "company_code": "X0000A"
}
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| 公共五字段 | | 是 | 见 3.1 |
| `order_id` | string | 是 | 旅通订单号 |
| `trade_id` | string | 是 | 旅通支付流水号 |
| `refund_bn` | string | 是 | 旅通退款单号。与渠道编码构成全局幂等键 |
| `refund_fee` | long | 是 | 退款金额，单位分，必须 **> 0**，否则 `E4001`「退款金额必须大于0」 |
| `user_code` | string | 是 | 会员编号 |
| `company_code` | string | 是 | 企业组编号 |

签名字段：公共五字段 + `order_id` `trade_id` `refund_bn` `refund_fee` `user_code` `company_code`。

超额退款、单据不存在、幂等冲突等业务错误统一映射为 `E4001`「请求参数或业务状态无效」，不回显中台内部错误码。

### 8.2 成功响应

```json
{
  "result": "success",
  "code": "E0000",
  "msg": "",
  "data": {
    "out_trade_no": "SC-PAY-...",
    "out_refund_no": "SC-REF-...",
    "refund_status": 0,
    "refund_fee": 5634,
    "refund_time": 1736735103,
    "refuse_reason": ""
  }
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `out_trade_no` | string | 商户支付单号 |
| `out_refund_no` | string | 商户退款单号（中台 `refundCaseNo`） |
| `refund_status` | int | `0` 待退款，`1` 退款成功，`2` 退款失败。受理成功通常为 `0` |
| `refund_fee` | long | 退款金额，单位分，取本次请求金额 |
| `refund_time` | int | 退款时间，Unix 秒。受理时尚无完成时间，填接口调用当前时间；键必须输出 |
| `refuse_reason` | string | 失败原因；没有时填空字符串，禁止 JSON `null` 或省略 |

受理成功表示中台已收下退款 Case（排队中 / 退款中），**不表示资金已退回**。最终结果用接口⑥轮询。成功 `data` 六个键必须齐全，详见 `docs/superpowers/specs/2026-08-27-rtmart-command-callback-hardening-design.md#82-申请退款--查询退款成功-data-字段始终输出`。

## 9. 接口⑥ 查询退款状态

POS 定时查询退款结果。旅通为 pull 模型，中台不主动推送。

| 项 | 值 |
|---|---|
| 地址 | `POST /api/rtmart/refund/query` |

### 9.1 请求

```json
{
  "app_key": "xx",
  "version": "v1",
  "timestamp": 1734019200,
  "nonce_str": "O4mxapNiWL1KvF6j",
  "sign": "Base64签名",
  "order_id": "LT-ORDER-001",
  "trade_id": "LT-TRADE-001",
  "refund_bn": "LT-REFUND-001",
  "user_code": "247",
  "company_code": "L0000A"
}
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| 公共五字段 | | 是 | 见 3.1 |
| `order_id` | string | 否（协议有） | 参与签名；中台按 `refund_bn` 定位 |
| `trade_id` | string | 是 | 旅通支付流水号 |
| `refund_bn` | string | 是 | 旅通退款单号 |
| `user_code` | string | 是 | 会员编号 |
| `company_code` | string | 是 | 企业组编号 |

### 9.2 成功响应

```json
{
  "result": "success",
  "code": "E0000",
  "msg": "",
  "data": {
    "out_trade_no": "SC-PAY-...",
    "out_refund_no": "SC-REF-...",
    "refund_status": 1,
    "refund_fee": 580,
    "refund_time": 1786098269,
    "refuse_reason": ""
  }
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `out_trade_no` | string | 商户支付单号 |
| `out_refund_no` | string | 商户退款单号 |
| `refund_status` | int | `0` 待退款，`1` 退款成功，`2` 退款失败 |
| `refund_fee` | long | 退款金额，单位分。成功/完成返回**买家实退金额**；处理中返回**渠道申请金额**；失败/人工处理值为 JSON `null`，键必须保留 |
| `refund_time` | int | 退款时间，Unix 秒。有完成时间用完成时间，否则取接口调用当前时间；键必须输出 |
| `refuse_reason` | string | 失败原因；没有时填空字符串，禁止 JSON `null` 或省略 |

内部状态到协议 `refund_status`：

| 中台退款状态 | 内部码 | 返回 `refund_status` | `refund_fee` |
|---|---|---|---|
| 退款成功 / 已完成 | 30 / 60 | `1` | 买家实退金额（缺失则按系统错误失败） |
| 退款失败 | 40 | `2` | 不返回 |
| 人工处理 | 90 | `0` | 不返回 |
| 待处理 / 排队 / 退款中 | 0 / 10 / 20 | `0` | 渠道申请金额 |

## 10. 错误码

协议码只能是下列枚举（`RtmartResponseCode`），不会把中台内部码（如 `1_012_xxx`）直接回给旅通。

| code | Word 文档含义 | 中台实际使用 |
|---|---|---|
| `E0000` | 成功 | 成功 |
| `E4001` | 验签缺少参数 | **广义参数/业务无效**：缺字段、`order_type` 非法、退款金额 ≤0、nonce 重放、凭证/会员无效、绑定缺失、超额退款、单号不存在、幂等等 |
| `E4002` | timestamp 不合法（过期 3 分钟） | 时间戳超出容差（默认 ±180 秒） |
| `E4003` | app_key 错误 | `app_key` 与配置不一致 |
| `E4004` | 签名错误（含不传 sign） | 签名缺失或 SHA1withRSA 验签失败 |
| `E5000` | 未知错误 | 适配器关闭、nonce 存储不可用、会员资料暂时不可用、未归类异常 |

接口②～⑥业务异常中，调用方可纠正的内部码（绑定缺失、超额、单号不存在、幂等冲突等）一律 `E4001`「请求参数或业务状态无效」；其余 `E5000`「系统错误」。

HTTP 状态码恒为 **200**，以 body 的 `code` 区分成败。

## 11. 调用顺序（联调）

```
商城 App 调 mall BFF 换 entryUrl
  → 中台签发 tk-xxx，向旅通换 HOME URL
  → App 打开旅通 H5
      → ① POST /member/resolve（token 换 user_code / mobile）
      → POS 扫码下单
      → ② POST /order/create（拿 cashier_url）
      → POS 打开收银台完成支付
      → ③ POST /payment/query（轮询 pay_status）
      → 需要取消：④ POST /payment/cancel
      → 需要退款：⑤ POST /refund/apply → ⑥ POST /refund/query 轮询
```

`user_code` 在整条支付/退款链必须与①的返回值一致。`trade_id` 是支付幂等与查询的主键；`refund_bn` 是退款幂等与查询的主键。

## 12. 与 Word 文档的差异（以代码为准）

| 点 | Word 文档 | 当前实现 |
|---|---|---|
| 接口路径 | 未给出商户 URL | `/api/rtmart/...`，测试域名 `apitest.kalaiwang.com` |
| 签名算法示例 | 文档末示例 sign 像 MD5 短串 | **SHA1withRSA + 标准 Base64**，不是 MD5 |
| `order_type=2` | 动态码必填 | 本期拒绝非 `1` |
| 接口① token | 未说明前缀 | 支持并剥离 `CXB_` |
| 接口① nonce 重放 | 未写 | 不做 Redis 防重放 |
| 接口②～⑥ nonce | 未写 | Redis `setIfAbsent`，TTL = 容差 × 2 |
| `company_code` | 示例写死 `L0000A` | 接口①返回凭证冻结快照；②～⑥按请求传入并做业务校验 |
| `E4001` | 仅「验签缺少参数」 | 覆盖缺参 + 业务状态无效 + nonce 重放 |
| 查询③/⑥ 定位键 | 同时给 order_id 与 trade_id/refund_bn | 必填校验看 `trade_id` / `refund_bn`；`order_id` 参与签名但查询不依赖 |

密钥、`app_key`、企业组编码以联调环境配置为准，不要把测试私钥写入仓库或日志。

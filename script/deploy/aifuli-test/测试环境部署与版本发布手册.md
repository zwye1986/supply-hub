# 爱福利测试环境部署与版本发布手册

现网 `58080` 的 mall/pay/erp/statistics（及完整八服务 systemd）只从 `aifuli-mall-pro` 发版；本仓脚本只安装/发布 gateway/system/infra/member。不要用本仓作为 cookbook 去 `systemctl` 启停或 `deploy.sh` 发布商城四进程。

## 1. 适用范围

本文适用于爱福利测试环境 `baseapp1`，部署根目录为 `/data/aifuli-test`。

本仓后端发版范围仅为 gateway / system / infra / member。mall / pay / erp / statistics 及现网完整八服务 systemd，见 `aifuli-mall-pro` 仓库 `script/deploy/aifuli-test/`。

当前部署方式为：后端使用 `systemd` 管理 Spring Boot Jar；后台管理端与 H5 由 Nginx 提供静态文件，并将接口统一代理到 Gateway。

生产环境目录应与测试环境保持同一结构，仅将根目录替换为 `/data/aifuli-prod`，并使用独立的 Nacos、Redis、MQ 消费组、XXL-Job 执行器和域名。

## 2. 测试环境架构

```text
浏览器 / 吾盛 H5
        |
        v
      Nginx
        |-- 静态文件：admin、h5
        `-- API / WebSocket --> gateway-server:58080
                                  |
                                  v
                       system / infra / member
```

现网 `58080` 八服务（另含 mall / pay / erp / statistics）拓扑只存在于 `aifuli-mall-pro`，本仓不再安装或发布那四个进程。

### 2.1 服务与端口

本仓脚本安装的服务：

| 服务目录 | systemd 服务 | 应用名 | 端口 | 职责 |
| --- | --- | --- | --- | --- |
| `gateway` | `aifuli-test-gateway` | `gateway-server` | 58080 | 唯一 API 入口、路由转发 |
| `system` | `aifuli-test-system` | `system-server` | 58081 | 用户、权限、租户、字典 |
| `infra` | `aifuli-test-infra` | `infra-server` | 58082 | 文件、配置、日志、WebSocket |
| `member` | `aifuli-test-member` | `member-server` | 58087 | 会员、地址、积分 |

mall / pay / erp / statistics（含 `mall-server` 聚合 `product` / `promotion` / `trade`）的端口、Jar 与 systemd 单元见 `aifuli-mall-pro`，不要在本仓执行对应 `deploy.sh` 或 `systemctl`。

### 2.2 对外域名

| 域名 | 用途 | 协议 | 静态目录 |
| --- | --- | --- | --- |
| `aifuli-test.qihaofu.cn` | 后台管理端 | HTTPS | `/data/aifuli-test/frontend/admin` |
| `aifulih5-test.qihaofu.cn` | 商城 H5、吾盛联调 | HTTPS | `/data/aifuli-test/frontend/h5` |

Nginx 配置文件：`/etc/nginx/conf.d/aifuli-test.conf`。仓库模板见 `script/deploy/aifuli-test/nginx/aifuli-test.conf`。线上 `server_name` 另含 `wusheng.qihaofu.cn`，改配置时只合并 location，禁止用仓库文件整份覆盖。

> 两个测试域名共用 `*.qihaofu.cn` 通配符证书。证书与私钥仅保存在服务器，不得提交到 Git 仓库。

## 3. 目录与日志

```text
/data/aifuli-test/
  apps/<service>/releases/<version>/   后端版本目录
  apps/<service>/current -> releases/  当前后端版本软链接
  apps/<service>/upload/               上传待发布 Jar 的固定目录
  frontend/admin/                      后台管理端静态文件
  frontend/h5/                         H5 静态文件
  logs/<application-name>/             Spring Boot 业务日志
  packages/<version>/                  上传的 Jar 临时包目录
  tmp/                                 前端、Nginx 配置等临时上传目录
```

查看 systemd 控制台日志：

```bash
journalctl -u aifuli-test-member -f --no-pager
```

查看业务文件日志，以 member 为例：

```bash
tail -f /data/aifuli-test/logs/member-server/member-server.log
```

Nginx 日志默认位于 `/var/log/nginx/`。

## 4. 首次后端部署

### 4.1 前置条件

1. 已安装 Java 21、Nginx，并创建 `aifuli` 系统用户。
2. `/data/aifuli-test` 目录已创建，且已执行 `script/deploy/aifuli-test/install-systemd.sh`。
3. Nacos 已存在 `aifuli-mall-test` namespace，Data ID 使用 `*-server-test.yaml`，Group 为 `test`。
4. MySQL、Redis、RocketMQ、XXL-Job、OSS 已为测试环境配置并可连通。
5. `application-test.yaml` 中 Nacos namespace 与 group 必须和 Nacos 保持一致。
6. 对 `supply-chain-test` 手工执行含中文的 SQL 时，客户端必须 `SET NAMES utf8mb4` 或 `--default-character-set=utf8mb4`。MySQL 的 `latin1` 实际是 cp1252，用默认 latin1 会话写入 UTF-8 字节会二次编码，读出来就是 `å¤§æ¶¦…`。应用 JDBC 已带 `characterEncoding=utf8`，不要在业务代码里再做 latin1 反解。

首次安装 systemd 单元时，将 `script/deploy/aifuli-test` 上传到服务器后执行：

```bash
cd /上传目录/aifuli-test
bash install-systemd.sh
```

### 4.2 发布顺序

本仓首次部署建议按以下顺序发布：

```text
system -> infra -> member -> gateway
```

mall / pay / erp / statistics 的发布顺序与 Jar 名称见 `aifuli-mall-pro`；本仓不要安装或发布这四个进程。

每个本仓服务只需要执行以下两步：将固定名称的 Jar 上传到该服务的 `upload` 目录，然后直接执行 `deploy.sh`。脚本会自动生成内部版本号、保留旧版本、切换软链接并验证启动状态。

以 member 为例：

```text
上传到：/data/aifuli-test/apps/member/upload/aifuli-module-member-server.jar
```

```bash
bash /data/aifuli-test/apps/member/deploy.sh
```

本仓服务的固定 Jar 名称如下：

```text
gateway     aifuli-gateway.jar
system      aifuli-module-system-server.jar
infra       aifuli-module-infra-server.jar
member      aifuli-module-member-server.jar
```

脚本会自动等待 10 秒检查运行状态；如发布失败会自动回滚上一版本。仍建议查看服务状态和日志：

```bash
systemctl status aifuli-test-member --no-pager
journalctl -u aifuli-test-member -n 200 --no-pager
```

### 4.3 商城四进程（mall / pay / erp / statistics）

现网 `58080` 的 mall / pay / erp / statistics 及完整八服务 systemd **只从 `aifuli-mall-pro` 发版**。

本仓已删除对应 systemd unit 与 prod `apps/{mall,pay,statistics}` 目录，请勿用本仓脚本在测试机上 `systemctl` 启停这些进程，也不要按本仓路径上传 `aifuli-module-{mall,pay,erp,statistics}-server.jar`。Nacos Data ID、Gateway 路由、端口与回滚步骤一律见 `aifuli-mall-pro` 仓库的 `script/deploy/aifuli-test/测试环境部署与版本发布手册.md`。


## 5. Nginx 与 HTTPS 部署

本地配置模板：`script/deploy/aifuli-test/nginx/aifuli-test.conf`。

将更新后的配置上传到服务器后执行：

```bash
install -m 644 /data/aifuli-test/tmp/nginx/aifuli-test.conf \
  /etc/nginx/conf.d/aifuli-test.conf

nginx -t
systemctl reload nginx
```

H5 证书路径：

```text
/etc/nginx/certs/aifuli-test/qihaofu.cn.pem
/etc/nginx/certs/aifuli-test/qihaofu.cn.key
```

私钥权限必须为 `600`。证书更新后执行 `nginx -t && systemctl reload nginx`，无需重启后端服务。

Nginx 已代理以下路径：

```text
/admin-api/     -> Gateway
/app-api/       -> Gateway
/infra/ws/      -> Gateway WebSocket
/doc.html       -> Gateway Knife4j
/webjars/       -> Gateway Knife4j 静态资源
/v3/api-docs    -> Gateway 聚合服务列表
```

`/doc.html`、`/webjars/`、`/v3/api-docs` 只配在管理端 443（`aifuli-test.qihaofu.cn`），不要抢 `/favicon.ico`。改完必须 `nginx -t` 再 `reload`。

## 6. 后台管理端发布

前端项目目录：`D:\java\projects\jierongproject\ai-fuliyun-web`。

测试环境配置文件为 `.env.test`，关键配置如下：

```dotenv
VITE_BASE_URL=''
VITE_API_URL=/admin-api
VITE_BASE_PATH=/
VITE_OUT_DIR=dist-test
VITE_MALL_H5_DOMAIN='https://aifulih5-test.qihaofu.cn'
```

构建命令：

```powershell
cd D:\java\projects\jierongproject\ai-fuliyun-web
pnpm build:test
```

要求 Node.js `>= 20.19`、pnpm `>= 8.6`。构建产物为 `dist-test`，将该目录内的所有内容上传至：

```text
/data/aifuli-test/frontend/admin/
```

验证地址：

```text
https://aifuli-test.qihaofu.cn/
```

登录后在浏览器 Network 面板确认接口请求为 `/admin-api/...`，不能出现 `localhost:48080`。

## 7. H5 发布

H5 项目目录：`D:\java\projects\jierongproject\ai-fuliyun-uniapp`。

使用 HBuilderX 打开项目，选择：

```text
发行 -> 网站-H5手机版
```

H5 `.env` 的测试关键配置：

```dotenv
SHOPRO_BASE_URL=https://aifulih5-test.qihaofu.cn
SHOPRO_TRIAL_BASE_URL=https://aifulih5-test.qihaofu.cn
SHOPRO_DEV_BASE_URL=http://127.0.0.1:58080
SHOPRO_API_PATH=/app-api
SHOPRO_WEBSOCKET_PATH=/infra/ws
SHOPRO_STATIC_URL=local
SHOPRO_H5_URL=https://aifulih5-test.qihaofu.cn
SHOPRO_TENANT_ID=1
```

构建产物通常为：

```text
D:\java\projects\jierongproject\ai-fuliyun-uniapp\unpackage\dist\build\h5
```

将该目录内的所有内容上传至：

```text
/data/aifuli-test/frontend/h5/
```

必须确认 `index.html`、`static/` 等目录已上传。验证地址：

```text
https://aifulih5-test.qihaofu.cn/
```

发布前确认 `SHOPRO_TENANT_ID` 是否为目标测试租户。错误的租户编号会导致商品、会员、订单数据不正确。

## 8. 日常版本更新流程

### 8.1 后端版本更新

1. 确认本次修改影响哪些本仓服务（gateway / system / infra / member）；只构建和发布受影响的服务。
2. 若有 SQL 变更，先在测试库备份后执行 SQL，再发布 Jar。
3. 在本地构建 Jar。mall / pay / erp / statistics 及 Mall 聚合 Jar 的更新见 `aifuli-mall-pro`，本仓不发布这四个进程。
4. 将新 Jar 上传到受影响服务的 `upload` 目录，文件名必须使用本手册第 4.2 节的固定名称。
5. 在服务器执行对应服务目录下的 `bash deploy.sh`。
6. 脚本自动生成版本号并完成启动检查；随后验证业务接口、日志和 Nacos 注册状态。
7. 脚本保留旧 `releases/<version>` 目录，暂不删除，便于回滚。

member 更新示例：

```text
先上传：/data/aifuli-test/apps/member/upload/aifuli-module-member-server.jar
```

```bash
bash /data/aifuli-test/apps/member/deploy.sh
```

### 8.2 后端手动回滚

当新版本启动失败或核心验证失败时，以 member 为例：

```bash
ls -1dt /data/aifuli-test/apps/member/releases/*
ln -sfn /data/aifuli-test/apps/member/releases/<上一版本号> \
  /data/aifuli-test/apps/member/current.next
mv -Tf /data/aifuli-test/apps/member/current.next \
  /data/aifuli-test/apps/member/current
systemctl restart aifuli-test-member
systemctl status aifuli-test-member --no-pager
```

数据库 SQL 一旦执行不能依赖 Jar 回滚恢复，必须提前准备对应的回滚 SQL 或数据库备份。

### 8.3 后台管理端更新

1. 更新 `.env.test` 后执行 `pnpm build:test`。
2. 上传 `dist-test` 内的全部内容并覆盖 `/data/aifuli-test/frontend/admin/`。
3. 使用浏览器无痕窗口或强制刷新，避免旧浏览器缓存。
4. 验证登录、商品管理、上传文件及 WebSocket 连接。

静态文件更新不需要重启 Nginx；只有修改 Nginx 配置或证书时才需要执行 reload。

### 8.4 H5 更新

1. 检查 `.env` 的 H5 测试地址和 `SHOPRO_TENANT_ID`。
2. 在 HBuilderX 重新发行 H5。
3. 上传构建产物全部内容并覆盖 `/data/aifuli-test/frontend/h5/`。
4. 使用手机无痕模式访问 H5，验证首页、商品详情、登录、下单和接口请求域名。

## 9. 配置与中间件变更原则

1. Nacos 的测试配置只修改 `aifuli-mall-test` namespace、`test` group 下对应的 `*-server-test.yaml`。
2. 修改数据库连接、Redis、MQ、XXL-Job、OSS 等基础配置后，重启受影响服务并检查日志。
3. 测试和生产必须使用独立 Redis 数据库、MQ 消费组、XXL-Job 执行器名称和 OSS Bucket，禁止混用。
4. 不要在 Git、部署文档、聊天记录中保存数据库密码、OSS 密钥、京东密钥或 Nacos 密码。
